Deep Dive · Agentic Core

LangGraph multi-agent pipeline

  • Intent routing — orchestrator.py classifies the query (property / market / ROI / scheduler / general) and selects an agent.
  • Specialist brief — the chosen agent produces a task brief that shapes Claude’s reasoning for that turn.
  • RAG context injection — top-5 listings + market reports retrieved and folded into the system prompt.
  • Conversation memory — last 3 exchanges threaded in for multi-turn continuity.
  • Shared typed state — AgentState TypedDict flows through every node.

Why ChromaDB, not OpenSearch Serverless?

OpenSearch Serverless bills a ~$11/day idle floor (2-OCU minimum, 24/7) — “serverless” doesn’t scale to zero. For a ~31-doc corpus, brute-force cosine over in-process ChromaDB is microseconds and free.

The container re-ingests on startup, so an ephemeral store is fine on Fargate. A deliberate cost/architecture trade-off — documented as an ADR.

Engineering Story · The Hard Bug

“The answer arrives all at once”

Symptom

7.9s of silence, then 110 chunks dumped in 0.04s. Streaming looked broken.

Root cause

Bedrock Guardrails default to synchronous stream mode — they buffer the entire response, evaluate it, then release everything at once. InvokeModelWithResponseStream can’t change that.

Fix

Rewrote the model layer onto the Converse / ConverseStream API and set streamProcessingMode = "async" — chunks release as generated while the guardrail still evaluates in parallel.

# tools/bedrock.py guardrailConfig = { "guardrailIdentifier": GUARDRAIL_ID, "guardrailVersion": version, "streamProcessingMode": "async", # ← the fix } client.converse_stream( modelId=PROFILE_ARN, system=[{"text": system_prompt}], # guardrail messages=user_turn, # skips our guardrailConfig=guardrailConfig, # dense prompt )

Result: first token in ~1.1s, trickles over ~6s. Malicious input still blocked (guardrail_intervened). Key learning: never attach a guardrail to a streaming call without async mode — it silently defeats streaming.

Safety & Trust

Defense in depth for a public LLM endpoint

Input sanitisation

2,000-char cap + regex detection of 6 prompt-injection patterns (“ignore previous instructions”, role-swap, <system>, [INST]…) before the model is ever called.

AWS Bedrock Guardrails

Managed content filters, denied topics, PII redaction, and contextual grounding — evaluated against the user turn & model output only.

Rate limiting

slowapi caps /api/chat at 20 requests/min per IP to contain abuse and runaway token spend.

Topic + error hardening

Strict in-prompt scope (Dubai real estate only); internal exceptions never leak to the client — sanitised messages only.

Subtle lesson: denied topics defined as “anything about <domain>” made the classifier block on-topic answers — scope must be expressed carefully, not bluntly.

What I Learned

The interesting failures

Streaming vs guardrails

A guardrail on a streaming call silently buffers everything. Solved only by moving to the Converse API’s async stream mode.

“Serverless” isn’t free

OpenSearch Serverless has an ~$11/day idle floor. Right-sized to in-process ChromaDB; kept the abstraction to swap back at scale.

Cross-region Bedrock IAM

Inference profiles route across regions — the task role needs InvokeModel in every profile region, not just us-east-1.

Cost as a design constraint

On-demand start/stop scripts + always-up data layer keep a full AWS app at ~$0/mo idle without losing the deployment.
