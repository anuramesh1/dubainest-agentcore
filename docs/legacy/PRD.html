Started: May 2026 Target: 14 days Author: IT Professional (15 yrs Java) Status: Planning complete

01 · Vision

What we're building

DubaiNest AI is a real estate enquiry website where users can ask questions in natural language about Dubai properties. Behind the chatbot, multiple specialised AI agents collaborate — one searches listings, another analyses market trends, another calculates ROI, and another schedules viewings. The system uses Claude Sonnet (via Amazon Bedrock) as its intelligence layer, orchestrated by LangGraph's multi-agent state graph.

This is a learning project designed to demonstrate agentic AI architecture, cloud-native deployment on AWS, CI/CD pipelines, and production-grade engineering thinking — all within a 2-week build sprint.

03 · Phase Plan

14-day build roadmap

Phase 1
Day 1–2
Foundation & GitHub setup

Establish the monorepo structure, developer tooling, and project conventions before any feature code is written.

  • GitHub monorepo — /frontend, /backend, /agents, /infra, /docs folders
  • Branch strategy — main (prod), develop (integration), feature/* branches
  • Pre-commit hooks — Black (Python), Prettier (Angular), ESLint
  • docker-compose.yml — run entire stack locally with one command
  • Root README.md — architecture diagram, setup instructions, tech decisions
  • .gitignore — Python, Angular, Terraform, .env files
  • GitHub Issues — create one issue per phase as project tracking
Phase 2
Day 2–4
Angular frontend — chatbot UI

Build the user-facing application: property listings, an AI chatbot widget, and a map view, in Angular 17 with Tailwind CSS.

  • Angular 17 scaffold — standalone components, no NgModule boilerplate
  • Tailwind CSS — integrated with Angular build pipeline
  • Chatbot widget — streaming SSE responses from backend, typing indicator
  • Property listing page — card grid with filters (area, price, type)
  • Property detail page — images, specs, ROI summary, enquiry CTA
  • Leaflet map view — ngx-leaflet, property pins, area overlays
  • Arabic/English toggle ★ — i18n with Angular's built-in i18n or ngx-translate
  • Responsive layout — mobile-first, works on all screen sizes
Phase 3
Day 4–6
FastAPI backend + data layer

Build the API layer that connects the frontend to the agent system, and populate the database with real Dubai property data.

  • FastAPI app — async, Pydantic v2 schemas, automatic OpenAPI docs
  • REST endpoints — /properties, /search, /enquiry, /health
  • WebSocket endpoint — /ws/chat for streaming agent responses
  • DynamoDB models — Property, Conversation, Lead tables
  • Property data scraper — Bayut / Property Finder public listings (BeautifulSoup)
  • Mangum adapter — wraps FastAPI for AWS Lambda deployment
  • Environment config — .env via pydantic-settings, per-environment overrides
Phase 4
Day 6–9
LangGraph multi-agent core ★ centrepiece

Design and implement the 5-agent collaboration graph. This is the core differentiator of the project — each agent is a specialised node in a LangGraph state machine.

  • LangGraph state graph — typed AgentState, conditional edges, human-in-loop checkpoints
  • Orchestrator agent — intent classification, routes to correct specialist
  • Property Search agent — queries DynamoDB, filters, ranks results
  • Market Intelligence agent — price trends, area statistics, supply/demand from public data
  • ROI Calculator agent ★ — rental yield %, mortgage vs cash analysis, break-even years
  • Scheduler agent — captures viewing preferences, confirms slots
  • RAG pipeline — ChromaDB locally, embeddings via Bedrock Titan, document chunking
  • Agent memory — conversation history persisted to DynamoDB per session
  • Bedrock integration — Claude Sonnet via boto3 / LangChain Bedrock wrapper
Phase 5
Day 9–10
Observability dashboard ★ wow-factor

A live admin dashboard showing which agent handled each turn, latency breakdowns, and token cost — demonstrating production engineering awareness.

  • Agent trace view — per-conversation timeline of agent handoffs
  • Latency chart — per-agent response time histogram
  • Token cost tracker — cumulative Bedrock spend by session and agent
  • Live log stream — WebSocket feed of real-time agent activity
  • CloudWatch integration — structured JSON logs, custom metrics namespace
  • Angular component — dedicated /admin/observability route, protected route guard
Phase 6
Day 10–11
CI/CD — GitHub Actions pipeline

Automated testing and deployment pipeline that runs on every push and deploys to AWS on merge to main.

  • Backend pipeline — pytest, mypy type check, Black lint, Docker build, push to ECR
  • Frontend pipeline — ng test (Karma/Jest), ng build, upload to S3, CloudFront invalidation
  • Environment secrets — AWS credentials, Bedrock config via GitHub Secrets
  • PR checks — all checks must pass before merge to develop or main
  • Deploy on merge — main branch triggers Lambda update + CloudFront deploy
Phase 7
Day 11–13
AWS deployment

Deploy the full stack to AWS within a strict cost budget. Infrastructure defined as code for reproducibility.

  • S3 + CloudFront — Angular static bundle, HTTPS, global CDN
  • AWS Lambda — FastAPI via Mangum, 512MB memory, 30s timeout
  • API Gateway — HTTP API + WebSocket API for chat streaming
  • Amazon Bedrock — Claude Sonnet model, us-east-1 region (best availability)
  • DynamoDB — on-demand billing, TTL on conversation records (90 days)
  • OpenSearch Serverless — swaps in for ChromaDB, 1 OCU minimum
  • AWS CDK / Terraform — all infra as code in /infra folder
  • AWS Budgets — $10/month alert, $20/month hard notification
  • IAM roles — least-privilege, separate roles for Lambda and CI/CD
Phase 8
Day 13–14
Docs, demo video + portfolio wrap

Polish the project for portfolio presentation — documentation, a live demo, and preparation for interview questions.

  • Architecture diagram — production-quality, saved to /docs/architecture.png
  • README overhaul — local setup in <5 commands, screenshots, live URL
  • Loom demo video — 3–5 min walkthrough of user journey + observability dashboard
  • Interview cheat sheet — /docs/DECISIONS.md, why each tech was chosen
  • Cost report — real AWS bill for the build period, annotated
  • Seed data — 50+ realistic Dubai property listings for demo

04 · Agent Design

5-agent collaboration model

All agents share a typed AgentState object. The Orchestrator routes intent via conditional edges; specialists return results back to state. Claude Sonnet is the LLM backbone for all agents.

🧠
Orchestrator
Classifies user intent, maintains conversation state, routes to the right specialist agent, synthesises final response.
🔍
Property Search
Queries DynamoDB listings, applies filters (area, budget, bedrooms, type), ranks results by relevance.
📊
Market Intelligence
Fetches price-per-sqft trends, area statistics, supply/demand data from public Dubai land department data.
💰
ROI Calculator ★
Computes rental yield %, mortgage vs cash-buy comparison, break-even analysis, and 5-year appreciation estimate.
📅
Scheduler
Captures viewing preferences (date, time, in-person vs virtual), confirms appointment slot, stores lead in DynamoDB.

05 · Portfolio Differentiators

What makes this stand out

Observability dashboard ★ selected
Live view of agent handoffs, per-agent latency, token costs, and log stream. Shows production-readiness thinking beyond just "it works".
ROI Calculator agent ★ selected
Turns the chatbot from an information tool into an active decision-support tool. Rental yield, mortgage analysis, break-even — domain-aware AI.
Arabic / English toggle ★ selected
Dubai's market is bilingual. One-click language switch using Angular i18n. Demonstrates product awareness and real-world market fit thinking.
Swappable vector DB design
ChromaDB locally → OpenSearch on AWS. The abstraction layer means zero agent code changes at deploy time. Great architecture story for interviews.
End-to-end type safety
TypeScript on Angular + Pydantic on FastAPI + typed AgentState in LangGraph. Full type coverage from UI to AI layer — rare in portfolio projects.
Infrastructure as Code
All AWS resources defined in CDK/Terraform. One command to spin up a fresh environment. Demonstrates DevOps maturity beyond just deploying manually.

07 · Decision Log

Architecture decisions & rationale

DecisionChoiceRationale
Frontend frameworkAngular 17+Java developer familiarity — DI, services, and modules mirror Spring patterns. TypeScript-first by design.
Backend languagePython / FastAPIAI/ML ecosystem lingua franca. LangGraph, LangChain, boto3 all Python-native. Pydantic gives Java-like typing.
Agent frameworkLangGraphVisual state graph = excellent interview demo. Explicit state typing. Supports human-in-the-loop and agent memory out of the box.
AI modelClaude Sonnet via BedrockEnterprise-grade, AWS-native, pay-per-token. Keeps everything in one cloud. No separate API key management.
Vector DB strategyChromaDB → OpenSearchChromaDB is zero-cost and in-process for local dev. Swapped for OpenSearch at deploy. Demonstrates good abstraction design.
DatabaseDynamoDBAWS-native, on-demand billing (near-zero for portfolio scale), no server to manage. TTL for conversation cleanup.
Backend hostingLambda + MangumCheapest option at portfolio scale. Lambda free tier covers most of the usage. Mangum adapter = zero code changes.
StylingTailwind CSSUtility-first works well with Angular. Smaller bundle than Material for a focused project. Modern, portfolio-friendly aesthetic.
